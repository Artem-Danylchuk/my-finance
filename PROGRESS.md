# Стан проєкту

## Зроблено

- Перевірено Git і правила ігнорування приватних даних та службових файлів; створено початковий коміт `6654bbd`.
- Прочитано правила проєкту, профіль Олі та перші рядки виписки. Проведено п’ять уточнень: їжа має три категорії; Wolt — доставка; місяці календарні; неповний жовтень показуємо за фактом із позначкою; результат — короткий HTML без переходів до операцій.
- Створено `PRD.md` і `IMPLEMENTATION_PLAN.md`, заповнено розділ «Проєкт» у `AGENT.md`.
- Зафіксовано початкові 4 500 PLN, один рахунок у PLN, визначення заощаджень і перелік фіксованих витрат.
- Створено `main.beancount`: відкрито всі рахунки проєкту, внесено початковий залишок через капітал, включено згенерований файл операцій.
- Створено `import.py`: усі CSV з `data/`, категорії лише з `rules.csv`, перше відповідне правило без урахування регістру, тег `#fixed` лише за правилами. Дублікати прибираються за датою завершення, описом, сумою та залишком; порядок банку збережено, зокрема при перекритті виписок.
- Імпорт повністю й атомарно перезаписує `transactions.beancount`; помилкові дані не псують попередній файл. Додано balance-твердження із колонки Balance на перше число після кожного попереднього місяця та на день після останньої операції для останнього місяця.
- Додано чотири нативні директиви `query` у `main.beancount`: витрати за категоріями; дохід, витрати, заощадження, відсоток і дата останньої операції; фіксовані та змінні витрати; операції без категорії, згруповані за місяцем і описом. Місяць включає рік, початковий капітал виключено з доходу, нульовий дохід дає невизначений відсоток (`NULL`).
- Запущено Fava у фоні командою `uv run fava main.beancount -p 5050`; адреса — http://127.0.0.1:5050/. Перевірено відповідь HTTP 200. Сервер працює, доки активний його процес; після зупинки його можна запустити тією самою командою.

## Поточний стан і перевірки

Імпорт, базовий облік і чотири місячні запити працюють; доступний локальний перегляд у Fava. Окремий короткий HTML-звіт ще не створений. На пряме прохання Олі `rules.csv` залишено без змін: Play, Rossmann і Decathlon поки потрапляють у `Expenses:Без-Категорії`, без тегу `#fixed`. Тому Play наразі входить до змінних витрат у запиті; це обмеження поточних правил, а не зміна визначення фіксованих витрат.

- `uv run python import.py`: імпортовано 142 унікальні операції, шість витрат залишилися без категорії. Перелік показано Олі в результаті роботи; самі операції не записуємо в Git.
- `uv run bean-check main.beancount`: код завершення 0, жодного повідомлення. Усі три звірки із банківськими залишками пройшли: на 01.09.2026, 01.10.2026 і 16.10.2026.
- Повторний імпорт поточної виписки: SHA-256 згенерованого файлу не змінився.
- `uv run python -m unittest -v test_import`: три тести пройшли. На вигаданих даних перевірено перекриття виписок, дедуплікацію, зворотний порядок часу всередині дня, дати й суми balance-тверджень, виявлення неправильного залишку, пріоритет Bolt Food перед Bolt, `#fixed`, невідомі витрати й доходи, повторний імпорт, збереження попереднього файлу після помилки та відмову при суперечливому порядку.
- `data/` не змінювалася. `transactions.beancount` залишається виключеним із Git; нових пакетів не встановлено.
- Кожен збережений запит виконано через `uv run bean-query main.beancount '.run "Назва запиту"'`; таблиці показано Олі. В останньому місяці дата останньої операції — 15.10.2026; це допомагає помітити неповний період, але сама дата останньої покупки не підтверджує повноту виписки.
- `test_queries.py` на вигаданих даних перевіряє всі чотири запити: від’ємні заощадження, місяць без доходу, місяць без витрат, розділення років, відсутність початкового капіталу в доходах, дату останньої операції, `#fixed` і невідомі витрати.
- Фінальна перевірка кроку: `uv run python -m unittest -v test_import test_queries` — усі чотири тести пройшли; `uv run bean-check main.beancount` і `git diff --check` — без повідомлень.
