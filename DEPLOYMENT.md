# Безкоштовна публікація для домашнього завдання

Готовий серверний застосунок — `tracker.py`, WSGI-вхід — `wsgi.py`. Він використовує наявний Flask із залежностей Fava, без AI й нових платних сервісів. Виписки в `fixtures/` штучні й входять до Git. Старі `app.py` і `report.html` залишаються локальним прототипом Олі; їх не публікуємо як телефонний трекер.

## Локальна перевірка

```sh
uv sync --frozen
uv run python verify.py
uv run python -m unittest -v test_tracker
uv run python run_local.py
```

Остання команда попросить придумати два окремі локальні паролі й збереже лише їхні хеші у змінних середовища процесу. Паролі не записуються у файли. Відкрити `http://127.0.0.1:5052/`, увійти як `marko` або `olya`. Це локальна перевірка; для здачі потрібна публічна HTTPS-адреса.

## PythonAnywhere Beginner

1. Створити безкоштовний акаунт і один Web app через **Manual configuration**, Python 3.12 або новіший. Скористатися безкоштовним субдоменом `імʼя.pythonanywhere.com`; нічого не оплачувати.
2. Завантажити цей репозиторій у `/home/імʼя/my-finance` або клонувати його після появи GitHub-адреси. Завантажити лише файли репозиторію: без `.env.local`, `.private/`, `data/` та `.venv/` із комп’ютера.
3. У Bash-консолі підготувати Python-середовище через uv і виконати `uv sync --frozen`, потім `uv run python verify.py`. Для Linux uv підходить офіційна команда встановлення з [документації Astral](https://docs.astral.sh/uv/getting-started/installation/). На хостингу має бути власне `.venv`, зібране для Linux.
4. У налаштуваннях Web app вказати virtualenv `/home/імʼя/my-finance/.venv`. В офіційному WSGI-конфігу додати шлях проєкту до `sys.path`, налаштувати середовище, потім імпортувати `from wsgi import application`. Не запускати `app.run()` у WSGI.
5. Змінні середовища процесу WSGI налаштувати до імпорту застосунку. Їхні назви наведено нижче; значення не класти в репозиторій або сам WSGI-код. Якщо панель не має редактора змінних, використати приватний env-файл **поза репозиторієм** із правами 600, з якого конфігурація хостингу заповнить `os.environ` до імпорту. Сам env-файл не роздавати HTTP-сервером і не додавати до Git.
6. У панелі Web увімкнути **Force HTTPS**, натиснути **Reload**. Перевірити, що WSGI передає `wsgi.url_scheme=https`; застосунок не довіряє довільному клієнтському `X-Forwarded-Proto`. Не робити статичних відповідностей на корінь проєкту, `.private` чи `fixtures`.
7. Відкрити адресу без cookie: має бути лише сторінка входу. Перевірити обидва логіни, місяці та додавання 1 PLN. Перезавантажити сторінку й Web app: запис має залишитися. Вийти й повторно перевірити, що звіт закритий.
8. На Free застосунок має місячний строк дії. У панелі перевірити, що його дата закінчення пізніша за 09.11.2026, і перевірити доступність перед здачею. Наявність коду не є доказом успішного розгортання.

Офіційні інструкції: [Flask на PythonAnywhere](https://help.pythonanywhere.com/pages/Flask/), [Free accounts](https://help.pythonanywhere.com/pages/FreeAccountsFeatures/), [HTTPS](https://help.pythonanywhere.com/pages/HTTPSSetup/). Free має обмеження диска й зовнішньої мережі; тут немає зовнішнього API або окремого сервера бази.

## Змінні середовища

| Назва | Значення |
|---|---|
| `TRACKER_SECRET_KEY` | Випадковий секрет не менш як 32 символи; не спільний із паролями |
| `TRACKER_OLYA_PASSWORD_HASH` | Scrypt-хеш окремого тестового пароля Олі |
| `TRACKER_MARKO_PASSWORD_HASH` | Scrypt-хеш окремого тестового пароля Марка |
| `TRACKER_PUBLIC_HOST` | Точне ім’я свого сайту без `https://` і без шляху |
| `TRACKER_DATABASE` | Необов’язково: абсолютний шлях SQLite поза HTTP-роздачею; за замовчуванням `.private/tracker.sqlite3` |

Згенерувати хеш приховано введеного пароля: `uv run python -c 'from getpass import getpass; from werkzeug.security import generate_password_hash; print(generate_password_hash(getpass("Пароль: ")))'`. Результат — секретне значення для середовища, а не для коміту. Секрет сесії: `uv run python -c 'import secrets; print(secrets.token_urlsafe(48))'`. Ці команди призначені для власної приватної консолі; паролі не вставляти в аргументи команд або чат.

## Дані, копії та спрощення

Канонічне сховище готівки — SQLite. Копію робити через SQLite backup, а не копіювання відкритого файлу бази; окрему копію зберігати поза сервером. Готівковий облік можна експортувати після входу; він проходить Beancount і не впливає на звірку банку. Початковий готівковий залишок невідомий, тому його не показуємо.

У першому телефонному варіанті немає завантаження нових CSV через браузер, редагування готівки, реєстрації користувачів, AI, фото чеків і Telegram. Входів рівно два; особисті записи відбирає сервер. Спільні — лише оренда та продукти; інтернет і світло залишаються особистими до окремої домовленості. Борг за кожен місяць показано до фактичних переказів компенсації.

## Що здати після розгортання

Потрібні фактична HTTPS-адреса, окремий тестовий логін і пароль, публічний GitHub-репозиторій та 5–10 речень про реально використаний хостинг. Пароль передати в Eduworkspace, а не в README. Поки хостинг і GitHub не підключено, посилання та опис успішної публікації не вигадуємо.
