# План збірки

Після кожного кроку оновлювати `PROGRESS.md` і робити коміт із коротким описом українською. Після змін в обліку обов’язково запускати `uv run bean-check main.beancount` і показувати результат; перевірка має пройти без повідомлень. Усі Python-команди виконувати через `uv run`, нових пакетів без дозволу не встановлювати. `data/` не змінювати.

## 1. Підготувати рахунки та правила категорій

**Зробити**
- Створити `main.beancount` для Beancount 3: валюта PLN, відкриття всіх рахунків із розділу «Проєкт» у `AGENT.md`, початкові 4 500 PLN на 31.07.2026 через рахунок початкового капіталу, включення `transactions.beancount`. Створити порожній файл операцій для початкової перевірки.
- Доповнити `rules.csv`: Play — телефон і фіксована витрата; Rossmann — косметика та побутова хімія; Decathlon — спорт. Перевірити відповідність опису зарплати правилу доходу. Зберегти три окремі категорії їжі та порядок Bolt Food перед Bolt; фіксованість операцій надалі позначати `#fixed`.

**Перевірити**
- Прочитати виписку без зміни її вмісту: формат, дати, валюта, стан операцій, комісії та відповідність початкового залишку. Якщо є непідтримувані значення, спочатку визначити їх обробку за фактичними даними.
- Зіставити приклади з правилами: Bolt Food і Wolt — доставка, Bolt і Uber — транспорт без `#fixed`, ZTM — транспорт із `#fixed`, Play — телефон із `#fixed`.
- Запустити `uv run bean-check main.beancount`; переконатися, що всі використані рахунки відкриті, початковий залишок не записаний як дохід.

## 2. Імпортувати виписки

**Зробити**
- Створити `import.py`: читати всі CSV у `data/`, застосовувати перше правило без урахування регістру, записувати операції з датою завершення в `transactions.beancount`. Для невідомих витрат використовувати `Expenses:Без-Категорії`, для надходжень без правила доходу — `Income:Інше`.
- Уникати дублів за ключем «дата завершення, опис, сума, залишок». Генерувати файл заново при кожному запуску; не редагувати його вручну. Для перевірки банківського залишку зберігати порядок рядків у виписці.
- Перевіряти коректність вхідних даних; помилки пояснювати з посиланням на файл і рядок. Не залишати частково перезаписаний файл операцій після помилки.

**Перевірити**
- Запустити `uv run python import.py`, потім `uv run bean-check main.beancount` без повідомлень.
- Звірити кількість унікальних операцій, суми надходжень і списань, кінцевий залишок із CSV. Перевірити, що нетиповий порядок часу всередині дня не порушує звірку.
- Повторити імпорт: результат не змінюється. На тимчасових копіях поза `data/` перевірити дубль рядка, невідомий опис та помилкову суму; вихідні виписки не змінювати.

## 3. Розрахувати місячні підсумки

**Зробити**
- Додати збережені запити нативною директивою `query`: витрати за категоріями й календарними місяцями; доходи, витрати та заощадження; витрати з тегом `#fixed` і без нього.
- Норму заощаджень рахувати як `(дохід − витрати) / дохід × 100%`; частки фіксованих і керованих витрат — від усіх витрат. Виводити витрати й доходи у зрозумілих додатних сумах, зберігаючи знак різниці заощаджень.

**Перевірити**
- Запустити `uv run bean-check main.beancount` і виконати запити через `uv run bean-query`.
- Незалежно звірити місячні підсумки з CSV: сума категорій дорівнює витратам; фіксовані плюс керовані дорівнюють витратам; дохід мінус витрати дорівнює заощадженням. Початкові 4 500 PLN не впливають на дохід.
- Перевірити від’ємні заощадження, нульовий дохід і нульові витрати на тимчасових даних поза `data/`; не ділити на нуль.

## 4. Згенерувати короткий HTML-звіт

**Зробити**
- Створити `report.py`, який читає перевірений облік і генерує автономний `report.html` українською: місячні доходи, витрати, заощадження в PLN і відсотках; суми категорій; фіксовані та керовані витрати в PLN і відсотках.
- Використати ті самі розрахунки, що перевірені на кроці 3. Показувати суми до двох десяткових знаків, відсотки до одного; обчислення виконувати без втрати точності грошей.
- Для поточної виписки явно позначити жовтень як неповний до 15.10.2026. Для наступних імпортів передавати підтверджену кінцеву дату покриття параметром `--through YYYY-MM-DD`, не виводити її з дати останньої покупки. Поточний запуск: `uv run python report.py --through 2026-10-15`.
- Обійтися без нових пакетів, зовнішніх ресурсів і переходів до операцій; при помилці обліку не створювати новий звіт.

**Перевірити**
- Згенерувати звіт і відкрити у браузері: усі три питання мають видимі відповіді для кожного місяця; продукти, доставка й кафе розділені.
- Звірити цифри зі запитами; перевірити позначку жовтня, відсутність прогнозу, читабельність і роботу без інтернету.
- Перевірити відмову генерації при помилці обліку та зрозумілий вивід для нульових знаменників.

## 5. Перевірити весь щомісячний сценарій

**Зробити**
- Оновити README короткою інструкцією: покласти нову виписку в `data/`, виконати імпорт, перевірку й генерацію звіту з датою покриття, відкрити `report.html`; для невідомих категорій доповнити `rules.csv` та повторити імпорт.
- Зафіксувати у `PROGRESS.md` фактичні результати перевірок і наступні дії.

**Перевірити**
- Виконати сценарій на поточній виписці від імпорту до HTML. `uv run bean-check main.beancount` має пройти без повідомлень, підсумки — узгодитися з випискою.
- Перевірити Git: `data/`, `transactions.beancount`, `report.html`, `.venv/` та `__pycache__/` ігноруються й не відстежуються; код, документація й `rules.csv` включені до відповідних комітів.
