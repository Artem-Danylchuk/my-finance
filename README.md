# my-finance — стартова папка воркшопу

Це заготовка особистого фінансового трекера, який ми зберемо на занятті 7 Warsaw IT School 5.0 разом із Claude Code.

## Що тут лежить
- `data/statement.csv` — вигадана банківська виписка Олі за серпень–жовтень 2026 року, 142 операції. Справжніх даних тут немає.
- `PERSONA.md` — хто така Оля і що вона хоче знати про свої гроші. На занятті ви відповідатимете агенту від її імені.
- `rules.csv` — правила, за якими операції потрапляють у категорії. Його можна відкрити в Excel чи Numbers, але на занятті правити його буде агент.
- `AGENT.md` — основні правила роботи агента; прочитайте їх на початку кожної сесії.
- `pyproject.toml`, `uv.lock`, `.python-version` — опис програм, які потрібні проєкту. Їх ставить команда `uv sync` з гайда підготовки.

## Як відкрити
VS Code → File → Open Folder… → оберіть цю папку `my-finance`. Потім Terminal → New Terminal.

Нічого в цих файлах до заняття міняти не треба.

## Як оновити місячний звіт

Додайте нову CSV-виписку в `data/`, потім із папки проєкту виконайте:

```sh
uv run python import.py
uv run bean-check main.beancount
uv run python report.py --through 2026-10-15
```

Перевірка `bean-check` має завершитися без повідомлень. У `--through` вкажіть дату, до якої банк надав дані: для поточної виписки це 15 жовтня 2026 року. Це дата покриття виписки, а не обов’язково дата останньої покупки.

Відкрийте `report.html` у браузері й оберіть місяць зверху. Звіт працює без інтернету; неповний місяць має позначку з датою. Під час генерації виконуються три збережені запити з `main.beancount`; оформлення береться з `report_template.html`.

У звіті «Наші гроші» є вкладки «Загальна», «Оля», «Марко». Загальна показує спільні витрати, оплати двох людей і компенсацію; Олина — її показники з урахуванням своєї частки від 1 жовтня. Маркова залишається закритою без особистих сум. Доступні перемикання мишею, стрілками клавіатури та клавішами Home/End. Входи, серверний захист і введення готівки з телефона ще не реалізовані; пріоритети всіх 18 фіч описані в `IMPLEMENTATION_PLAN.md`.

Невідомі витрати залишаються без категорії до доповнення `rules.csv`. Погоджені правила для Play (телефон, фіксована витрата), Rossmann (косметика та побутова хімія) і Decathlon (спорт) уже додано. Після узгодженої зміни правил повторіть імпорт, перевірку та генерацію звіту. Виписки, `transactions.beancount` і `report.html` не комітяться.

## Продовження: спільний бюджет

Локальний файл містить особисті дані Олі та спільні підсумки із вигаданими даними Марка. Позначку демонстрації видно у звіті. Окремих входів ще немає.

`shared.py` рахує спільні оренду й продукти 50/50, оплати кожного та компенсації за місяць. Наприклад, Оля оплатила 100 PLN, Марко — 40 PLN: частка кожного 70 PLN, Марко компенсує Олі 30 PLN. Компенсація не збільшує витрати. У поточному звіті перекази компенсацій ще не вводяться, показано борг до їх внесення. Порожній набір записів не підтверджує відсутність витрат у виписці Марка.

`household_report.py` підключає обидва джерела до звіту. Для персональних показників він додає в пам’яті проводки розподілу й виконує ті самі збережені запити Beancount. Банківський залишок не змінюється. Поруч із витратами за власною часткою показано фактично оплачені з банку витрати. При різному покритті виписок підсумок неповний; у ньому враховано всі відомі оплати й окремо вказано дати обох джерел. Особисті покупки й зарплата Марка в HTML не передаються.

Для 1–15 жовтня в демонстрації: спільні витрати — 4 864,25 PLN, оплати Олі — 4 177,84 PLN, Марка — 686,41 PLN. Марко компенсує Олі 1 745,66 PLN. Сума двох часток точно дорівнює спільним витратам; різниця в грошах між частками виникає через округлення кожної покупки.

Початок спільного обліку — **1 жовтня 2026 року** (`household.json`). Попередні місяці автоматично не перерозподіляються; борг інших місяців у місячний розрахунок не переноситься.

### Вигадана виписка Марка

`examples/marko.csv` містить 16 вигаданих операцій за 1–15 жовтня. Це приклад другого формату, а не експорт конкретного банку: розділювач `;`, дата `ДД.ММ.РРРР`, десяткова кома, колонки `ID;Data księgowania;Opis;Kwota;Saldo;Waluta;Status`. Початковий залишок — 6 200 PLN; дохід — 10 500 PLN, витрати — 1 253,69 PLN, кінцевий залишок — 15 446,31 PLN. Усі значення демонстраційні.

```sh
uv run python import.py --demo-marko
uv run bean-check demo-marko.beancount
```

Команда створює окремий перевірений `demo-marko.beancount`, зберігає власника й ID банківської операції. Для категорій використовуються наявні `rules.csv`. Залишок перевіряється після кожного рядка; повторення одного ID не подвоюється, суперечливий ID відхиляється. При помилці попередній демооблік зберігається. Для оновлення спільного HTML достатньо звичайної команди `uv run python report.py --through 2026-10-15`: вона читає демонстраційний CSV за `household.json` й перевіряє його перед заміною попереднього звіту.

Перевірки проєкту:

```sh
uv run python -m unittest -v test_import test_queries test_report test_shared test_marko test_household_report
uv run bean-check main.beancount
```
